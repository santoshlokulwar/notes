New architecture

Q1 What is JSI in React Native’s New Architecture? +

JSI (JavaScript Interface) is a C++ layer that lets JS talk to native code without the old bridge. It avoids JSON serialization overhead, can run synchronously where appropriate, and underpins Turbo Modules and Fabric.

Q2 What are Turbo Modules? +

Turbo Modules replace legacy native modules: they use JSI for direct, faster (optionally synchronous) calls, lazy loading, and better performance than bridge-based modules.

Q3 What is Fabric rendering? +

Fabric is the new renderer: JSI-based C++ UI pipeline with synchronous layout options, better alignment with concurrent React, and less bridge overhead than the old UIManager + shadow thread model.

Rendering & lists

Q4 What is the Virtual DOM in React Native? +

React still builds a JS tree of your UI. Reconciliation diffs that tree; updates are applied to native views, not a browser DOM.

Q5 FlatList vs map() for long lists? +

FlatList virtualizes: it mounts only visible rows (+ small window). Mapping thousands of Views kills memory and JS thread. Use FlatList / SectionList for large data.

Q6 What is list virtualization? +

Only a slice of items is rendered and recycled as you scroll, keeping node count and work bounded.

Q7 Overlapping views without position — what helps? +

Use zIndex (and elevation on Android) so the intended view draws on top when siblings overlap in the same parent.

Hooks & navigation

Q8 useEffect vs useLayoutEffect +

useEffect runs after paint — good for subscriptions, logging, most data work. useLayoutEffect runs after DOM/native layout but before paint; use when you must measure or mutate layout to avoid flicker (blocking).

Q9 What is React Navigation? +

The common JS routing library for RN: manages navigation state and transitions via stack, tab, drawer, and other navigators.

Q10 What is Universal Linking / deep linking (concept)? +

HTTP/HTTPS links open your app (or store) on the right screen. iOS Universal Links and Android App Links require domain verification and OS configuration alongside React Navigation linking setup.

Production & performance

Q11 How do you remove console.log in React Native production? +

Use the Babel plugin transform-remove-console enabled only for production builds so Metro strips logs at compile time.

Q12 What usually causes RN performance problems? +
  • JS thread blocking (heavy sync work on main JS bundle)
  • Unnecessary re-renders
  • Large lists without virtualization
  • Heavy legacy bridge traffic (improves with New Architecture)
  • Memory leaks (listeners, timers, subscriptions)
Q13 How can you fetch live / real-time data? +

Polling, WebSockets, GraphQL subscriptions, or real-time DB SDKs. WebSockets are often the most efficient for true push streams.

Q14 How do push notifications work (high level)? +

App registers with FCM (Android) / APNs (iOS). Server sends to the provider; OS wakes or delivers to the app. You handle tokens, permissions, background modes, and notification channels (Android).

Q15 React Native 0.81 — what stands out? +

Broad Android 16 support with edge-to-edge defaults, experimental faster iOS precompiled builds, better errors/DX, legacy SafeAreaView deprecation, JSC moved to community package, stricter env/Metro expectations.

Q16 Pressable vs TouchableWithoutFeedback? +

Pressable is the modern primitive: flexible children, hit slop, ripple on Android, pressed state styles. Touchables are older; TouchableWithoutFeedback gives no visual feedback — use when you wrap non-text custom UI and handle feedback yourself.

Q17 What is Flipper used for? +

Flipper is a desktop debugger platform; plugins inspect layout, network, Redux, databases, crash logs, etc. (ecosystem has shifted over time; still useful in many RN setups.)
