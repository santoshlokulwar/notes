Core concepts

Q1 What is state uplifting (lifting state up)? +

State uplifting means moving state from a child to the nearest common parent so several children share one source of truth. That keeps data flow one-way and keeps siblings in sync.

Q2 What is JSX? +

JSX is a syntax extension that looks like HTML in JavaScript. It compiles to React.createElement (or equivalent) calls so you can describe UI in a declarative way.

Q3 What is the Context API and when do you use it? +

Context lets you pass data through the tree without prop-drilling every level. Use it for rarely changing global-ish data (theme, auth user, locale). Avoid putting everything in context or you can trigger wide re-renders.

Q4 Functional components vs class components — why prefer functional today? +

Functional components with hooks are the default in modern React: simpler mental model, easier composition, no this binding issues, and alignment with concurrent features. Class lifecycle methods map to hooks (useEffect, useLayoutEffect, etc.).

Hooks & performance

Q5 What is the difference between useMemo and useCallback? +

useMemo memoizes a computed value so you skip expensive recalculation when deps are unchanged. useCallback memoizes a function reference so child components that depend on referential equality (React.memo) do not re-render unnecessarily.

Q6 What is debouncing in UI handlers? +

Debouncing delays executing a function until the user stops firing events for a set time (e.g. search input). It cuts work versus running on every keystroke.

Redux & data

Q7 What is Redux Thunk? +

Redux Thunk is middleware that lets you dispatch functions, not only plain action objects. Inside the thunk you can run async code and call dispatch / getState.

Q8 Describe the Redux architecture at a high level. +
  • Single store — one global state tree
  • Actions — plain objects describing what happened
  • Reducers — pure functions: (state, action) → new state
  • Dispatch — sends actions to the store
  • Optional middleware (thunk, saga) for side effects
Q9 Is data in the Redux store encrypted by default? +

No. Redux stores plain JS objects in memory. Encryption or secure persistence is your responsibility (e.g. secure storage, obfuscation) if you need it.

Q10 What is React Query (TanStack Query)? +

TanStack Query (formerly React Query) manages server state: fetching, caching, background refresh, deduping requests, and keeping UI in sync with remote data — complementary to client state libraries.

Types & ecosystem

Q11 What is static type checking (e.g. TypeScript)? +

Types are checked at compile time (or by the type checker before bundle). Variable and function types are known or inferred so many bugs are caught before runtime.

Q12 What is GraphQL? +

GraphQL is a typed query language for APIs. Clients request exactly the fields they need from often a single endpoint, which reduces over-fetching and under-fetching compared to naive REST.

Q13 What is a peer dependency? +

A peer dependency declares that your package expects the host app to install a compatible version (e.g. react, react-dom) instead of nesting its own copy — avoiding duplicate React and version conflicts.

Q14 What’s new in React 19 (high level)? +

React 19 builds on React 18 with Actions for async forms, the use() hook for reading promises/context, stronger Suspense patterns, resource preload APIs, and more mature Server Components support.

Q15 What are micro frontends? +

Micro frontends split the UI into independently deployable pieces (by team or domain), composed in the browser or via a shell app — similar ideas to microservices for the frontend.
