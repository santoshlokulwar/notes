Redux Toolkit interview points

Q1 Why Redux Toolkit over plain Redux? +

RTK removes boilerplate with configureStore and createSlice, includes good defaults, and encourages scalable patterns by default.

Q2 How can reducers "mutate" state in RTK? +

RTK uses Immer under the hood. You write draft mutations, Immer produces the next immutable state safely, so reference changes remain predictable.

Q3 What is createAsyncThunk and when to use it? +

It standardizes async workflows by generating pending/fulfilled/rejected actions. Use it for request lifecycle handling when RTK Query is not the right fit.

Q4 RTK Query vs thunk-based fetching? +

RTK Query provides cache, dedupe, invalidation, and request status out of the box. Thunks give more manual control but require more custom caching logic.

Q5 How do you organize RTK slices in enterprise codebases? +

Keep feature folders with slice, selectors, async logic, and tests together. Export minimal public API from each feature and avoid cross-feature state coupling.
