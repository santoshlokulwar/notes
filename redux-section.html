Redux core concepts

Q1 Explain Redux data flow in one minute +

UI dispatches an action, reducer calculates next immutable state, store updates, subscribed UI re-renders. Flow is predictable because state changes only through dispatched actions.

Q2 Why immutability is important in Redux? +

Redux relies on reference changes to detect updates efficiently. Mutating existing objects can hide changes, break memoization, and cause stale UI bugs.

Q3 What problem does middleware solve in Redux? +

Middleware intercepts dispatched actions for side effects like API calls, logging, analytics, retries, and async orchestration, while reducers stay pure and synchronous.

Q4 How would you structure Redux store for large apps? +

Use feature-based slices, normalized entities, clear ownership boundaries, and shared selectors. Keep UI state separate from domain/cache state for maintainability.

Q5 When would you avoid Redux? +

For small apps with minimal shared state, Redux can be unnecessary overhead. Local component state + context or lightweight stores can be simpler and faster to iterate.
