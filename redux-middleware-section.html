Redux middleware interview topics

Q1 What is Redux middleware in practical terms? +

Middleware sits between dispatch and reducers. It can intercept actions to run side effects, transform actions, or block/redirect flows before state updates.

Q2 Why not put async calls inside reducers? +

Reducers must stay pure and synchronous. Async work in reducers breaks predictability, time-travel/debugging assumptions, and makes state transitions non-deterministic.

Q3 How does thunk middleware change dispatch behavior? +

Without thunk, dispatch expects plain action objects. Thunk allows dispatching functions that receive dispatch and getState for async orchestration.

Q4 Middleware order: why does sequence matter? +

Actions flow through middleware in registration order. Logging, auth, error handling, and retry behavior can differ based on chain order, so order should be intentional and documented.

Q5 When to write custom middleware vs use existing tools? +

Use existing middleware for common needs (thunk, logger, analytics adapters). Write custom middleware when behavior is domain-specific, cross-cutting, and not cleanly owned by one feature slice.
